# Native continuous Fire and explicit UI choice

Source baseline: `1de343e`; upstream gesture semantics inspected at `e677235` and `5027d7d`, CLI lifecycle at `ed70618`. The parent integrates the published CLI/backend changes separately. This port does not change the runner protocol or replace the existing scoped Composer request/viewing wrapper.

An upward microphone drag of at least 40 CSS pixels, before the existing three-second hold fires, starts hands-free Fire. Pointer release keeps it listening; the next microphone tap unlocks and releases the final utterance. Keyboard Space and the existing hold retain push-to-talk behavior. The locked status and hint are localized. A sampled microphone RMS above 0.02 marks speech; a voiced segment ends after more than 800 ms quiet or more than 20 seconds since speech began, sampled every 100 ms. Silence before speech does not generate empty messages.

Each recorder owns its final chunks, optional recognition preview and stopping deadline. The next locked recorder can start while the prior recorder is finishing or its transcript is being processed. The browser adapter reuses one microphone stream and one resumed AudioContext/level source across that handoff. An unlocked final onstop releases the real tracks and level source immediately, even when Whisper or message confirmation is pending. Cancel, navigation, membership loss, errors and ending-watchdog expiration revoke recorder callbacks, pending permission/resume completion and sampling; a failed old generation cannot stop or publish into a replacement session.

Transcription and ordinary messages remain serialized behind the existing acknowledgement plus canonical-message checks. Unconfirmed writes are never automatically replayed. Retained unsent audio is bounded to eight queued segments / twice the existing 4 MB audio limit; exceeding it visibly stops the continuous capture. Stopping recorders are also bounded and expire after 20 seconds. Explicit Discard clears the unsent backlog/work generation, so a later utterance cannot silently drain discarded audio. These are client resource limits, not additional server credentials or an alternate mutation policy.

Home and onboarding in both maintained frontends expose the accessible **Nova UI / New UI** switch. It changes only the current URL's `ui=svelte` selection, preserving pathname, other query parameters and hash. It creates no global default or preference affecting other tabs/users. Native layout uses the existing Tailwind utilities; the maintained default frontend keeps its existing rendering path.
