# Membership flags and stored connection projections

The Agents membership lookup still uses the original room/person SQL predicate and row presence as authorization. Its optional `claude_on` scalar now normalizes explicit SQLite 0/1 and historical null/missing values, validates the public boolean through the shared Claude result schema, and falls back to false for malformed values. Text such as `"0"` or `"false"` cannot enable the flag through JavaScript truthiness. Malformed row containers do not establish membership.

Connection SQL results are read as unknown. A schema-derived identity/scope projection and runtime HTTP(S) URL/credential-pair checks run before operational use or listing. Invalid required rows are isolated from valid listing neighbors. Cached tool/context containers remain optional: invalid columns become empty caches, then their existing per-item runtime validators retain valid siblings. The final public connection and complete connection list are parsed against the shared schemas before leaving the Worker.

Valid stored values, including empty display titles and epoch-zero creation times, are unchanged. A null or corrupt title uses the actual validated URL host for display; no identity is fabricated. A null or invalid historical creation time remains honestly null: `Connection.created_at` now permits null. Older strict native clients already rejected those malformed rows; vanilla already received null values and does not depend on this field. New connection creation still writes an actual timestamp. Credential material is never defaulted or exposed; inconsistent or malformed pairs cannot silently fall back to a different remote authorization mode.

Owner deletion is deliberately separate from executable/display metadata. It validates only original id/book/owner, retains the original owner-membership join and owner-only deletion check, and can remove an owned malformed URL or display row. The existing connection identity is used for session cleanup and notification; placeholders never select a target.

The actual SQLite consumer fixture invokes `connOps.list`, `getConn` and `deleteConn` through a D1-shaped SQLite test adapter, with malformed URL, nullable/scalar display damage, invalid credential pairs, malformed nested cache siblings, valid zero, private-peer filtering and owner-negative cleanup. The actual Hono Agents handler consumes SQLite scalar rows; integer affinity converts a stored numeric string to integer, so a CAST expression separately supplies a genuine TEXT `"0"` query result while `"false"` remains stored text. These are explicit SQLite/consumer fixtures, not a deployed D1, remote MCP, OAuth or production migration receipt.
