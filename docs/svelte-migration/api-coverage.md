## Reading the matrix

`src/api.ts` defines `AppType = typeof uploadsApi` and the separate signed-out `authApi` as `AuthAppType`. `build:api-types` emits declarations; `svelte/lib/client/api.ts` supplies `client()` / `authClient()` via `hc<…>`. Backend imports in these clients are type-only. The matrix's client paths are relative to `client().api`, unless prefixed `auth`. `B` means `books[":id"]`; `C` means `B.connections[":cid"]`; `S` means `sandboxes[":sid"]`. Thus `B.post.$post` is a concrete inferred Hono method, not a handwritten URL wrapper. Named request/response schemas live in `shared/schemas.ts` unless stated otherwise. `—` means no request payload; it does not imply no path/query parameters.

**Auth A:** signed-in middleware in `src/index.ts`; missing session produces 401 `UNAUTHENTICATED`. API mutations also pass the global same-origin/cross-site guard (403). **M:** additionally current room membership. **O:** additionally an owner-scoped lookup, not arbitrary object-ID access. Response parsing belongs to the named native adapter; cancellation, identity/opening/room generations and no automatic uncertain-write retry belong to its owner. HTTP 200, an inferred type, and a command ACK each establish different things.

In particular, no blanket “all statuses tested” follows from R or a complete UI suite. Exercise actual outer auth/origin middleware as well as service doubles where the security claim requires it.
