# Native runner Fire parity

Original source checkpoint against upstream main `3b86acb`, based on merged `2d1b6ae` with the separate backend protocol prerequisite `5f1c8dd` (local equivalent `0101429`). Do not cherry-pick the prerequisite copy when integrating native commits.

Dedicated-tab semantics follow upstream `d9fe028`, included in merged main `868b375` / canonical `6b58be8`. The on/off, STT and authenticated state contracts stay the same; the runner opens a separate Haiku Claude for this room and closes that dedicated tab on exit. It does not switch or restore the original room Claude model.

The old fast-model generation, per-pause POSTs, card activity shimmer, first-use cost dialog, and Stop-to-review message are retired. Fire now opens the person's dedicated Fire Claude through `{on}`, reflects authenticated runner `fireState` reports, records one utterance, and on release sends audio to the real Whisper endpoint. Browser recognition supplies preview and the existing fallback only. The resulting transcript is an ordinary captured-thread message through the existing Composer request adapter, so current viewing metadata belongs to the same canonical adapter as typed messages.

Empty-composer desktop Space held 350ms enters recording; a tap inserts a space. Nonempty-composer holds retain ordinary dictation. Outside editable/button controls, desktop Space held 300ms records and release sends. Mic tap retains dictation, 3s enters Fire, and subsequent taps toggle recording. Escape and Leave request closure of the dedicated Fire Claude; `off` is the runner confirmation. A missing report remains explicitly unconfirmed rather than claiming the tab closed. The listening dot appears from the start of recording, including while Haiku opens, uses the Studio destructive token and Tailwind pulse, and becomes static under reduced motion.

Recorder ownership fences permission promises, chunks, browser recognition, recorder stop/error, STT results and message completion by immutable account/room/thread/session/utterance. Permission and HTTP work have independent bounded leases; an ignored late permission result is disposed. One-second recorder chunks enforce the shared 4MB cap before indefinite browser buffering. Release before permission, blur/hidden/Send intent, membership loss, navigation and disposal stop owned media and prohibit late speech writes. Synchronous room departure hooks request closure of the dedicated Fire Claude before releasing the scope; private transcripts are cleared on departure. On/off has no server request revision, so tab closure is not claimed from HTTP success or silence; native code cannot promise ordering of arbitrary delayed runner reports.

The personal channel remains the singleton socket owner. Fire reports are delivered only through its current authenticated socket, account and exact active Book connection, with guards repeated between reentrant listeners. No per-room socket or global private cache was added.

Normal message ACK and canonical delivery stay separate. A positive correlated command result and bounded own-author/thread/text/files/baseline match together confirm a transcript; timeout/disconnect retains it without automatic resend. Definite prequeue refusal permits only an explicit retry, guarded by the captured utterance intent. A user may discard an uncertain utterance after reviewing the conversation. As with existing Composer messages, the wire result has no canonical message ID; identical concurrent own-author messages remain an acknowledged ambiguity of payload correlation.

Seventeen replacement pure cases and a replacement actual native Composer DOM case are authored, plus a personal-channel reentrant/identity case. Existing ordinary dictation/late-after-Send/dialog-focus tests remain. Author receipt: owned sixteen-path Node formatting passed, and the focused native Fire plus personal-channel suite passed 26 tests and 110 assertions in 1.73s. Three source-review findings have explicit regressions: synchronous Leave cannot queue a later on request, cancellation while recorder.stop is pending suppresses late chunks/onstop, and canonical delivery requires a positive correlated ACK as well as the bounded canonical candidate. The two asynchronous fixture assertions now wait for actual owner refusal/unconfirmed state instead of assuming a fixed microtask count. The authenticated runner phase is captured after narrowing before its state-update callback. Full UI/types, DOM, real runner/Whisper, browser microphone and real hardware gates for this final source remain pending; earlier root build/DOM results apply to the pre-followup checkpoint only. No provider fixture, old fast-model browser audit, deployment, or real speech acceptance is claimed.

The dedicated-tab followup changes only localized status copy, the listening indicator and these semantics notes. Controller/RPC/state ownership and the earlier test receipt remain unchanged; no actual dedicated-runner or microphone acceptance is inferred from a text/indicator change.
