# Inactive IconButton candidate: paired N1 diagnostic evidence

This receipt describes the isolated candidate branch (`a624ad3` plus test-only `b81ed49`), based on `c5bce86`. The runtime candidate and harness remain unintegrated; only this evidence is approved for retention. It must not be integrated or treated as a performance improvement before paired evidence. That base already includes the strict CPU failure instrumentation (`3c8a010`, equivalent to the separate `b8de174` source checkpoint). A control for this experiment must use the same base/instrumentation rather than attributing unrelated changes since published `139573a` to this candidate.

The production change removes nested Button and Icon component instances from IconButton. The native button keeps the same ButtonProps-derived API, shared buttonVariants/cn recipe, ghost/icon defaults, native ref, type, disabled/loading behavior, busy/label/title attributes, forwarded attributes and handlers. Icon.svelte exports a parameterized top-level glyph snippet; both the default Icon component and IconButton render exactly that SVG/catalog. Button.svelte also exports its existing loading-indicator snippet, so default Button and IconButton keep one spinner definition. No raw HTML, new glyph data, CSS, palette, feature reduction, owner/cache or public API was added. Exported snippets follow the [official Svelte module-scope rule](https://svelte.dev/docs/svelte/snippet#Exporting-snippets).

Three actual DOM equivalence cases are authored in the existing ui-panels suite. A typed test-only Svelte harness compares the candidate with the prior Button+Icon composition using the real shared primitives. The cases cover all six variants, class overrides, attributes and exact catalog paths/namespace; reactive loading/disabled/type/icon updates, stable nodes and bound refs through child unmount/remount; click/keyboard/pointer handlers, handler replacement, focus, real form submission and disabled suppression. Semantic element trees ignore only framework comment anchors and whitespace/attribute order. DOM-node assertions use booleans so a failed comparison cannot recursively format an entire browser object graph.

Author checks: seven owned paths formatted successfully and the existing variant/merge pure test passed eight assertions in 1.63s. In a separate frozen-install BugMachine worktree, API declaration emission and strict Svelte checking passed with zero errors/warnings. Tooling initially identified three untyped test callback parameters; the test-only `b81ed49` follow-up makes their PointerEvent/KeyboardEvent types explicit. Tooling then passed, and the three actual Svelte DOM equivalence cases passed 72 assertions in 2.79s. No production code changed after the original candidate checkpoint. Source-level removal of component layers does not establish closure attribution, saved bytes, heap reduction, hardware performance or acceptance.

The measurement protocol was one paired, nonexclusive N1 experiment per control/candidate with the same exact fixture, browser, throttling, workloads, readiness, fonts and lifecycle cycles. A private distinct driver may adjust only the experimental repetition lower bound so N1 can run; the canonical driver keeps its minimum seven repetitions and all budgets unchanged. The private driver diff and SHA must be retained, every output labeled NOT_ACCEPTANCE, and CPU failures/partial heap evidence retained without filtering or repair. A useful result would justify the separate full seven-run acceptance gate; it cannot substitute for that gate.

## Actual paired N1 diagnostic receipt — NOT_ACCEPTANCE

The serial BugMachine experiment completed at control `c5bce86` and candidate `b81ed49`, using Chromium 158.0.8127.18, 4x CPU throttling, public network fonts, the same long fixture, three history pages, 30 scroll frames and 20 lifecycle cycles. Each source ran eight original trials (one warmup and one measured trial per variant/device), then four separate discarded diagnostic trials. Both original cohorts passed execution; all 16 budgets in each cohort remained **unverified**, and each driver correctly exited 1. Neither source meets the required seven-run cohort. The machine was declared nonexclusive.

| Native measured metric                              |      Control |    Candidate | Observed difference |
| --------------------------------------------------- | -----------: | -----------: | ------------------: |
| Mobile settled post-GC JSHeapUsedSize               | 21,023,360 B | 20,558,772 B | −464,588 B (−2.21%) |
| Desktop settled post-GC JSHeapUsedSize              | 20,853,352 B | 20,464,412 B | −388,940 B (−1.87%) |
| Requested entry JS/CSS gzip reference, both devices |    358,667 B |    359,035 B |     +368 B (+0.10%) |

This is a modest observed heap decrease with an entry-byte increase, not proof of a stable performance improvement or component-level memory attribution. The reference gzip total describes actually requested built assets, not module-level gzip allocation or transfer bytes. Settled heap is measured after lifecycle cycles; it is distinct from the extra diagnostic's initial post-GC snapshot.

The strict CPU parser rejected both control native diagnostics for `delta-negative` (mobile sample 1108; desktop sample 657). Candidate mobile was also rejected for `delta-negative` at sample 1520; candidate desktop and all vanilla diagnostics passed. Therefore there is no paired valid native initial-heap/CPU comparison. No invalid profile was repaired, filtered, replaced or treated as zero. These observations do not identify the reason for an earlier published run's invalid profile.

The private driver changed only the repetition lower bound from seven to one; the canonical source and minimum-seven budget assessor were untouched. Both private copies were removed, and no raw heap remained in the task temporary directory after completion. The compact [N1 receipt](icon-button-layer-N1.json) records exact source/driver/metrics hashes, per-device measurements and closed CPU rejection counts. Full safe metrics remain in the task artifact archive; raw heap contents and private run logs are not committed. A full matched seven-run gate remains necessary before any acceptance claim.

Decision: retain the existing compositional Button/Icon implementation. The candidate remains inactive; no full acceptance run is scheduled for this candidate because these N1 observations do not justify its byte increase or establish reliable heap savings. This decision does not waive any performance budget.
