# Controlled Chromium Fire gesture proof (source only)

`native-fire-gesture-browser.ts` exports a helper for the real disposable Worker audit. It creates a fresh authenticated profile through the existing fixture and reloads once to install native media observations. The synthetic input is a 12-second looping PCM sine tone, not microphone hardware or a stored user recording. `writeFireGestureTone(privateOutput)` creates it; append `fireGestureBrowserArgs(tonePath)` (including Chromium's native `--disable-speech-api` switch so the optional browser recognition preview cannot contact a separate speech service) to the actual Chromium launch before invoking `auditNativeFireGesture(profileFixture)` as an independent audit. Main-runner wiring is intentionally left to the parent to avoid overlapping its current browser/profile changes.

The helper requires the actual visible Composer, holds its real microphone pointer for the existing three-second activation, validates the real same-origin Fire-on HTTP response, then checks that the original physical button still owns the same real pointer capture after Svelte publication. It slides that same held pointer upwards, releases it, and requires the locked status, a single native stream/context, a running context and positively sampled voiced RMS. Escape must produce the actual Fire-off acknowledgement and release all native audio tracks/context while the same button remains mounted. There must be zero STT requests and zero ordinary message writes. Failure to meet these assertions remains failure; no canonical/API/WS responses are mocked.

The tone has no quiet interval; Escape occurs before a 20-second voiced segment can complete. This deliberately avoids invoking Whisper or a real Haiku provider. The real Worker's Fire handler performs its authorized membership SQL update before acknowledging; the helper does not seed D1 or claim it controls an external runner. A server response is not proof that a real desktop Haiku tab opened or closed.

The native getUserMedia/AudioContext observers preserve native calls and return values. They retain a few actual track/context references to read their lifecycle states, so this is not a garbage-collection or heap-retention benchmark. They record only counts, pointer identity and RMS-threshold counts, never audio buffers, device labels, cookies, request payloads or credentials. Actual browser profile/context ownership and `finally` cleanup remain bounded; failure phase and metadata are written to `native-fire-gesture.json`, including cleanup failure.

The Web Speech preview is explicitly outside this audit; the actual recording, level observation and gesture paths stay enabled. No browser, compiler or generated tone has been run for this source checkpoint. Real iOS touch capture, hardware permissions/autoplay, actual codecs/Whisper and real runner completion remain separate gates. The helper does not substitute for the existing full application/permission/security/browser audits.
