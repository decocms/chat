The [official snapshot schema](https://learn.microsoft.com/en-us/microsoft-edge/devtools/memory-problems/heap-snapshot-schema#locations) defines location tuples by metadata field names. `object_index` is an offset into the flat numeric nodes array, not a node ordinal or ID. Extra numeric fields remain supported; when present, `script_object_index` must also be an aligned, in-range node offset. [DevTools' location map](https://chromium.googlesource.com/devtools/devtools-frontend/+/e343bdfafbbee2aac647db0915cb766dcaf04122/front_end/entrypoints/heap_snapshot_worker/HeapSnapshot.ts) uses that offset. DevTools links numeric script IDs via `String(location.scriptId)` to its debugger model.

V8-reported source location is not necessarily an allocation call site. [V8's generator](https://raw.githubusercontent.com/v8/v8/main/src/profiler/heap-snapshot-generator.cc) associates functions, generators and ordinary objects with function or constructor definition positions. Grouped self size therefore cannot establish the module retaining or allocating these objects. It is not retained size, dominator ownership, RSS, a complete accounting of allocations, or performance acceptance.

The pure model validates relevant node/location metadata widths and names, all numeric tuple values, safe integer totals, string/type index bounds, node ID uniqueness, aligned/in-range object offsets, and unique location associations. Missing locations are unverified. An empty location table reports all nodes unattributed. Unknown node type labels become the fixed `other` bucket. Invalid layouts produce only a closed failure reason.

Only external JS observed by the same trial's trusted public-asset registry is eligible. HTTP(S) paths must exactly agree with their canonical public keys, with no userinfo, fragment, encoded path or normalized traversal. Exact observed/script URLs may retain version queries internally; neither origin nor query is emitted. This is registry consistency, not a new origin authorization policy. Exact script ID, script URL and served byte SHA must agree with sanitized `Debugger.scriptParsed` provenance; source and served hashes remain separately labeled. Eval, sourceURL, live edit, duplicate script IDs, unmatched hashes and inline HTML remain unattributed. Only guarded public JS asset keys, hashes, fixed node types, counts and self-size totals leave the model. Node names, strings, script IDs, URLs, coordinates, graph arrays and raw heaps never enter artifacts. Coverage exposes nodes without locations and locations without trusted source matches.

The existing capture still writes UTF16LE chunks to a capped private file outside uploaded artifacts, parses once, and deletes raw data in `finally`. Optional attribution consumes that same transient parse. It does not change raw retention, cleanup, original summary or strict CPU behavior. The observed asset builder is extracted without changing its existing CPU filtering or output.
