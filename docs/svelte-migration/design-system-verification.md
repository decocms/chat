# Managed Studio and atomic UI verification

The `Studio and atomic design-system browser` workflow builds the exact checked-out application and MCP assets, then runs `scripts/native-application-ci.ts --suite design-system` on a disposable Ubuntu runner. This is a new verification path, not a passing runtime receipt. M4/M5 final visual/manual acceptance remains open.

The runner accepts only the fixed `application` and `design-system` suites. No arguments retain the existing application suite. The design-system suite requires the exact checked-out `TEST_APP_REVISION`, uses its own default report/private directories, synthetic `DEV_EMAIL`, random local session secret, private local D1/R2 state, models off, and loopback Worker. It reuses the existing readiness/schema check, owned process groups, cancellation and cleanup. No production credentials or resource writes are used. Raw Worker logs/storage/private variables are excluded from uploaded artifacts. A browser deadline rejects as well as signalling children so the runner reaches its existing kill/reap cleanup.

Two child processes have separate named phases and result directories. A failed gallery does not silently skip Inbox; either failure fails the whole suite. Cancellation/timeout stops the suite and never launches another child. Each result records the requested source revision. This workflow is separate from the performance cohort and does not change its workloads, instrumentation, thresholds or acceptance.

The old design-system script compared CSS-loaded/unloaded **legacy shell** elements around a native Inbox island, with a minimum of 20 legacy nodes. Full NativeApplication has no such host. That hybrid-only proof is retired explicitly; its threshold is not reduced to zero and the old result is not reused as final-app evidence. Current separation remains covered by `check:vanilla`, browser client-boundary/style checks and the independent default-variant integrated browser/security/HMR receipts. None of these is relabeled as the retired hybrid containment experiment.

The earlier script's `.kN` badge, `#swDlg` switcher, waits-only profile response and in-room modal assumptions are obsolete. The in-place RoomInbox closes with its real close control; Escape/return-focus remains checked on the actual Home/global Inbox Dialog and search Dialog. Inbox input sections are fetched from the actual `/api/inbox` client path, not inferred from a delivered profile hint alone.

Artifacts are `gallery/results.json`, gallery screenshots/diagnostic HTML, `inbox/results.json`, `inbox/inbox-results.json`, controlled Inbox screenshot/Axe findings, browser logs and `runner.json`. Independent real-Root profile coverage continues through the existing application suite; its Studio/Axe/keyboard evidence does not imply the gallery was exercised. Record exact workflow/source/artifact hashes only after execution, retaining failed phases rather than treating source registration as acceptance.

The local Linux process regression `bun test scripts/managed-browser-phase.test.ts` passed one test/eight assertions in 1.79 seconds with Bun 1.4.4. It starts one owned Node process which ignores SIGTERM and proves the real deadline rejection reaches finally, SIGKILL and reap within three seconds. This checks runner cancellation only; no gallery, Inbox, compiler or browser execution was performed locally. A source comparison also confirms the entire gallery assertion body is unchanged from `249e1e9` modulo formatting.
