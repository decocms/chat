# Isolated Fire provider protocol fixture

SOURCE CHECKPOINT: this boundary has author-focused SDK/HTTP evidence; no Worker/browser acceptance is claimed. The complete real-Worker browser phase is a separate pending step. No canonical API, Book, D1, R2, WebSocket, UI or document protocol is mocked or bypassed.

The default Fire model path still constructs the same OpenRouter provider with the configured production key and existing model/settings. Only an explicit trusted `FIRE_API` setting can select the local protocol fixture. It requires a nonempty `DEV_EMAIL` and exactly `http://127.0.0.1:<1..65535>/api/v1/chat/completions`; other hosts, credentials, encoded/normalized paths, queries, fragments and malformed values fail closed before model or room-data HTTP work. No invalid value falls back to OpenRouter.

The local provider uses an inert SDK key and an endpoint-bound transport. It sends only JSON/Accept headers, omits credentials, refuses redirects, bounds request and response body bytes to 256KiB and preserves the SDK's real request/structured-response protocol. The SDK needs a callable fetch implementation; its platform properties are preserved by a Proxy while every invocation is intercepted. Unread rejected request streams and oversized response streams are cancelled. Real environment keys are never passed into this local provider or forwarded as headers. This is a trusted DEV-only test seam, not a user-selectable endpoint or a production permission.

Tests cover exact configuration refusal, unchanged default transport identity, actual AI SDK generateText/Output.object over loopback HTTP, absence of authorization/cookie/key forwarding, redirect/different-endpoint refusal, and method/content/body-budget rejection before HTTP. Backend helper tests belong only in worker-test type coverage and an isolated Bun test process, so AI module mocks and Worker ambient types cannot contaminate unrelated DOM/tooling cohorts.

The strict external test server answers only bounded, known synthetic Fire prompts and valid OpenRouter structured-output shapes. Simulated model output does not prove real-provider intelligence, speech hardware/service delivery, quality or cost. Production defaults and existing checkEmbed/room/file authority remain unchanged. Original seven core stages, twenty lifecycle cycles, eight profiles and security gates must remain intact when the new browser phase is added.

Initial author receipt before the response/cancellation hardening: three-file Node Prettier passed and four isolated actual SDK/HTTP tests passed 44 assertions in 4.09s. The reviewer then identified the missing response cap and unread-request cancellation; both are addressed in source with an additional stream-cancellation fixture. The final isolated SDK/HTTP run passed five tests and 53 assertions in 1.94s. The new Request-stream test first exposed a stalled cancellation caused by copying a Request stream; the helper now validates metadata first and consumes/cancels the actual source body without a tee. Strict backend/worker types remain pending. New tests are registered only in worker-test types and their own isolated RPC Bun process.
